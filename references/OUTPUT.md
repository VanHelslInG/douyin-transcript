# 产物、配置与二次开发

## 目录结构

```
<稿件目录>/
├─ raw/
│  ├─ 2025-07-30 17.22.39-标题.mp4 → 2025-07-30 17.22.39-标题.txt
│  └─ ...                              # 一条一个 txt，ASR 原文，未被术语表污染
├─ 口播稿件合集.md                      # 全文汇总（表格 + 逐条正文）
├─ 索引.csv                            # 序号/发布日期/发布时间/文件名/时长/字数/状态
├─ 进度.html                           # 转写进度可视化
└─ .dyasr_meta.json                    # 文件名→时长 旁挂元数据，别删
```

`.dyasr_meta.json` 是刻意设计的：源视频往往转写完就删（几十 GB），而 `raw/*.txt`
里不含时长。没有它，`rebuild` 之后时长列会全部变 0。

## 配置文件 `~/.dyasr/config.json`

| 键 | 默认 | 说明 |
|---|---|---|
| `device` | `auto` | `auto` / `cuda` / `cpu`。`auto` = 有 CUDA 就用 |
| `fmodel` | `paraformer` | `paraformer`（准）/ `sensevoice`（更快，中文标点仍走 ct-punc） |
| `hotword` | 空 | 热词，空格分隔。命令行 `--hotword` 优先 |
| `batch_size_s` | 300 | 单批音频秒数，显存紧张时调小（60–120） |
| `fuzzy_threshold` | 0.95 | 模糊纠错阈值，越高越保守；调到 0.85 抓得多但会误伤 |
| `min_chars` | 100 | 少于此字数视为无效稿，用于过滤中断半成品 |
| `douk_repo` | 见文件 | 采集器仓库地址 |
| `douk_commit` | 见文件 | 锁定版本；清空则跟随默认分支 |

改配置：`dyasr config --device cpu --fmodel sensevoice`
（直接编辑 json 也行，但改完要保证是合法 JSON。）

## 两层纠错

| 层 | 文件 | 机制 | 适合 |
|---|---|---|---|
| 精确 | `~/.dyasr/terms.tsv` | `错词<TAB>正字` 直接替换 | 你确切知道 ASR 错成什么样 |
| 模糊 | `~/.dyasr/hotwords.txt` | 拼音相似度（pypinyin + rapidfuzz） | 只知道正确写法，抓各种变形 |

两层都只作用于产物，`raw/*.txt` 永远是 ASR 原文。执行顺序：先精确、后模糊。

模糊层有三条防误伤约束（都是实测被误伤逼出来的）：
窗口内必须全是汉字/字母数字（否则「情绪、价值」会被吞成「情绪价值」）、
窗口与目标长度差 ≤1（否则「生育」会变「生育率」）、互为子串时跳过。

多音字是它的盲区：`沉没成本` 的「没」读 mò，但 pypinyin 默认读 méi，
所以「沉默成本」抓不到——这类必须写进 `terms.tsv`。

## 术语表 `~/.dyasr/terms.tsv`

```
# 错词<TAB>正字
结构性发债	明股实债
婚债市场	婚恋市场
```

- **分隔符必须是 Tab**，不是空格；`#` 开头为注释。
- 长词自动优先匹配，避免「婚恋市场」被短词先切开。
- 只作用于产物，`raw/*.txt` 永远是 ASR 原文 —— 保留可回溯的原始证据。
- `rebuild` 会打印每条规则的命中次数，命中为 0 的规则通常是写错了。

ASR 的系统性错字绝大多数是**领域术语 + 人名**，通用表覆盖不了。
建议第一次转写完成后先读几篇，把高频错字补进表，再 rebuild。

## 时间排序（合集与索引）

`core.sort_media()` 解析文件名前缀 `YYYY-MM-DD HH.MM.SS` 排序（升序＝由旧到新），
**不用 mtime**。原因：mtime 是下载时间，同一批下载会让顺序完全错乱，
拿去做趋势分析会直接得出相反结论。

解析不出日期的文件排到末尾，`rebuild` 会告警。想让它们进时间线，
把文件名改成 `2025-01-01 12.00.00-标题` 这种形式即可。

## 代码结构

| 模块 | 职责 |
|---|---|
| `cli.py` | 参数解析、退出码、子命令分发 |
| `paths.py` | 家目录、config 读写 |
| `core.py` | 探测/清洗/排序/编号选择/进度页/产物生成。**零第三方依赖**，保证 rebuild 能在任何机器跑 |
| `cookie.py` | 四种格式的 Cookie 解析、导入、有效期检查 |
| `fetch.py` | 采集层：clone 采集器、绕开交互、跑下载、定位产物目录 |
| `listing.py` | 作品清单：编号、页面顺序还原、JSON 输出 |
| `transcribe.py` | 转写层：设备解析、模型常驻、逐条容错、断点续跑、按选择转写 |
| `clean.py` | 清理源视频（只删媒体，保留稿件与元数据） |
| `rebuild.py` | 产物层：只读 raw，重排 + 纠错 + 重生成 |
| `doctor.py` | 环境自检（文本 + JSON 双输出） |
| `terms.py` | 术语表解析与套用 |

想扩展的话，`core.build_outputs()` 是唯一的产物出口 —— 想加"按题材归类""生成
JSON 抓取结果""输出 SRT"之类，都在这里改，`transcribe` 和 `rebuild` 会同时受益。

## 编号口径与「置顶」（list / transcribe）

`core.parse_stem()` 解析文件名前缀 `YYYY-MM-DD HH.MM.SS`，`core.sort_media()` 按它排序。
但抖音的置顶作品可能是很旧的视频，**文件名里没有"置顶"这个概念**。

所以 `list` / `transcribe` 的编号规则是：

1. 若 `<媒体目录>/页面顺序.txt` 存在 → 按它的行序编号（01 = 第一行 = App 里第一条）。
   这份文件由 Agent 从作品页读到顺序后写入，`core.reorder_by_page()` 用「文件名包含该行」
   做匹配，未匹配的接在末尾。
2. 否则 → 发布时间倒序（最新在前），并在输出里明确提示无法还原置顶。


## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 有失败项（单条转写失败）或环境阻断 |
| 2 | 缺输入（缺 Cookie、缺链接） |
| 130 | 用户 Ctrl+C 中断（已完成的会保留） |
